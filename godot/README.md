# Alpha Hex · First Frontier

Open **project.godot** with the standard **Godot 4.7.2** editor and press **F5**. This is the complete native project; no .NET edition, external art or packages are required. `engine-version.txt` records the tested editor patch.

Grow a village, assign its people to work, discover stone beyond the fog, research quarry tools, and build a reinforced watchtower to open another frontier. Models, trees, yards, roads, people and carts are generated by code.

## First village and frontier

1. **Build [B]** a cottage on `(0,1)` and a forager lodge on `(-1,1)`. Select the building's plot and use its inspector action to place it. Assign the lodge one worker using **Workers [T]** or the inspector. Cottages start empty and supported migrants move in automatically, one per 90 simulated seconds.
2. Build a woodcutter on `(-1,0)`, an iron mine on `(1,0)`, and a foundry on `(1,-1)`. Assign each one worker. These connect directly to the hall. Watch goods arrive before spending them.
3. Add a second cottage at `(0,-1)`, keep food supplied, and allocate newcomers to the production you need. Keep **6 timber and 1 metal** for another resource claim. Trees and ore are finite; hand gather from owned deposits when a chain needs help.
4. At six citizens, **Research [R]** Frontier surveying. Claim `(0,2)` and build a watchtower; the cottage at `(0,1)` connects it. It reveals stone at `(0,5)` without granting ownership.
5. Research Stoneworking and then Quarrying tools (eight citizens). Claim `(0,3)`, `(0,4)` and `(0,5)`. Road the first two; build and staff a stone quarry on the third. Its output must arrive at the hall.
6. At ten citizens, research Frontier masonry using stone, then reinforce the watchtower for **12 timber, 4 metal and 16 stone**. Explore the new land and continue. Farming, nurseries and deep mining support further growth.

The current slice supplies one new stone/tool/masonry chain, with expansion up to radius 16 / 817 hex coordinates. There is no victory screen. An automated route reached the first reinforcement in 15.6 simulated minutes using hand gathering; this is not a measured human session. Weeks of meaningful content and replayability remain a longer-term goal.

The desktop UI targets landscape windows at least 1024×700 and scales from a 1440×900 reference layout, including Retina fullscreen. Text and buttons scale with the window; the 3D world keeps its native rendering resolution. Restart an already-running game after updating the display configuration. Touch handlers are present; synthesized gesture checks are not a physical-device pass. No export or iOS device has been verified.

## Saves

Choose **Menu [M] → Save & Exit** to save your village and close the game. The next launch resumes that save. If saving fails, an error is shown and the game stays open for retry. Normal window closure also checks save success when autosaving is enabled.

The game advances only while playing. Autosave runs every 30 seconds. `frontier.json`, its fallback `.bak`, and a single `previous.json` archive live in Godot's **AlphaHexFrontier** user-data directory. On macOS: `~/Library/Application Support/AlphaHexFrontier/`.

**Menu → Begin a new settlement** archives the current town before replacing it. **Previous settlement** loads that one archive. **Import Unity save…** accepts schema-1/2 `alpha-hex-save.json` files, preserves towns, known terrain, goods, reserves, jobs and travelling cargo, and leaves the source file unchanged. It also archives the current Godot town. Unused legacy research points retain their original uses. Invalid saves cannot partially replace the active town; a failed startup load pauses autosave until an explicit successful save or replacement.

## Source and checks

`core/` owns game rules and persistence. `runtime/` renders state and issues validated commands. `tests/` loads the actual simulation, including a resource-funded frontier scenario. There is no separate C# implementation required to run this project.

With the Godot executable on PATH, run these commands from this folder:

```sh
godot --path . --headless --editor --import --quit
godot --path . --headless --script res://tests/simulation_checks.gd
godot --path . -- --qa
godot --path . -- --qa --qa-display
```

The rendered commands create screenshots under `qa-output/` and exit. `--qa` runs the frontier smoke session; adding `--qa-display` instead checks native fullscreen, button dimensions, resizing and scaled mouse input. QA starts fresh and does not load or save your normal settlement. Keep source `.uid` files; omit `.godot`, `qa-output` and private saves from redistributed source.

This local prototype has no multiplayer, combat, arbitrary tunnels, offline production, additional resource tiers, tool durability or audio. The first playtest should examine workforce choices, resource reserves and whether another frontier feels worth developing.
